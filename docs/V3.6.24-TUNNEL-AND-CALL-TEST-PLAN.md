# OHLI Social v3.6.24 — test plan sebelum digunakan publik

## A. Build CI (wajib)
1. Upload `OHLI-Social-Source-v3.6.24.zip` ke root repository GitHub.
2. Jalankan workflow `Build OHLI Social Server APK`.
3. Pastikan step `Build Android-native cloudflared executables` berhasil untuk `arm64-v8a`, `armeabi-v7a`, dan `x86_64`.
4. Pastikan `Verify APK contains Android tunnel engines` menunjukkan ketiga ABI.
5. Download artifact `OHLI-Social-Server-APK-v3.6.24`.

## B. Tunnel pada perangkat Android (wajib)
1. Backup direktori data server sebelum mengganti APK.
2. Install APK hasil workflow di HP host dan izinkan notifikasi foreground service.
3. Nyalakan server lokal OHLI. Buka dari browser di perangkat yang sama melalui `127.0.0.1`/port yang ditampilkan dan pastikan halaman merespons.
4. Buka panel `Cloudflare · Server lokal ke publik` dan tekan `MULAI QUICK TUNNEL`.
5. Tunggu sampai status `ONLINE` dan URL `https://....trycloudflare.com` muncul. Jika gagal, catat status/error lengkap; jangan membagikan URL yang statusnya belum ONLINE.
6. Salin URL ke HP kedua dengan jaringan seluler (bukan Wi-Fi yang sama). Login dengan akun uji dan pastikan chat serta feed merespons.
7. Tekan Stop, pastikan URL lama tidak lagi dapat dipakai. Start ulang dan pastikan link baru dapat muncul.
8. Matikan internet host selama 60 detik, nyalakan kembali, lalu pastikan tunnel reconnect dan URL aktif; selama internet mati, pengunjung publik memang tidak bisa mengakses host.
9. Reboot HP host dengan server dan tunnel sebelumnya aktif; periksa apakah keduanya mulai kembali. Periksa juga pengaturan pembatasan baterai merek HP.

## C. Kamera VC dan LIVE (dua HP fisik)
1. Login akun uji A pada HP 1 dan akun B pada HP 2.
2. Mulai VC. Pastikan video teman penuh layar dan preview lokal kecil berbentuk persegi panjang membulat.
3. Ketuk preview lokal; pastikan tampilan utama dan preview bertukar.
4. Ganti depan ke belakang lalu kembali ke depan pada kedua HP. Pastikan video teman tetap memenuhi stage layar, preview kamera sendiri berupa tile portrait membulat di pojok, kedua layar menerima video, tidak hitam, dan indikator kamera sesuai.
5. Akhiri lalu mulai ulang VC untuk memastikan track lama dilepas.
6. Mulai LIVE sebagai A, gabung sebagai B. Pastikan stage satu host penuh layar; preview host tidak berupa lingkaran tengah.
7. Ganti kamera host, lalu minta B tampil dan ganti kameranya sendiri. Pastikan host dan B sama-sama melihat video baru.
8. Uji izin kamera ditolak, kamera sedang dipakai aplikasi lain, dan perangkat hanya memiliki satu kamera. UI harus tetap memberi pesan yang jelas dan tidak memutus stream lama bila pergantian gagal.

## D. Regresi data dan administrasi
1. Login 2 akun uji; pastikan pengguna biasa tidak dapat melihat daftar admin atau mengubah role.
2. Masuk panel admin; lihat akun terdaftar/online, nonaktifkan, suspend sementara, blokir sesuai fitur, pulihkan akun, dan soft-delete akun uji.
3. Pastikan akun yang dinonaktifkan tidak dapat login/akses API; pulihkan dan pastikan login kembali.
4. Pastikan akun, chat, postingan, Story, dan media lama masih ada setelah update APK.

## E. Catatan hasil
Catat model HP, versi Android, ABI, nama jaringan (Wi-Fi/seluler), hasil dan screenshot/log. Jangan mencatat password, OTP, token, atau cookie dalam laporan. Build atau tes yang belum dijalankan tetap dicatat sebagai BELUM DIUJI.
